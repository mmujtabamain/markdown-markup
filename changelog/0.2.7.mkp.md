# 0.2.7

From three hosts' reports: a first visit whose widgets push the text down while MKP loads, a pack widget a host wants to draw with its own code, and a pack's own type that a document couldn't read. Nothing written for 0.2.6 changes meaning or look.

## Breaking

- **Nothing for documents or packs.** MKP's root now carries `data-mkp-theme` where it carried `data-theme`; the stylesheet still reads `data-theme` set on the root by a host, but a host's own CSS or tests that looked for `data-theme` on `.mkp-root` should look for `data-mkp-theme`.

## New

- **Nothing moves on a first visit, with no server.** On a reader's first visit the prose showed at once and each widget appeared a second later, when MKP had loaded, pushing the text below it down. A first paint now reserves each widget's box at the height it will have:
  - `mount(el, bundle, { onSizes })` reports each top-level widget's height at the element's width, once drawn and when it changes; the host keeps those few numbers with the document (`mergeSizes` keeps the four latest widths).
  - `mkp-outline.js`, about 3 KB gzipped with no compiler and no React, draws the next first paint from the source alone: `outline(source, sizes, { width, prose })` gives the prose (drawn by the host's renderer) and a quiet placeholder per widget (`aria-hidden`, in a container marked `aria-busy`), at the measured height, or between widths along a line.
  - `mount(el, bundle, { places: true })` draws each widget into its placeholder from one runtime and touches nothing else; each box takes its widget's own height in the same frame. Measured in Chromium with prose between and below two widgets: layout shift 0 with kept sizes, at desktop and phone width; a document never drawn before gets 160 px boxes and moves once.
  - Each top-level widget, fenced or `:::`, has a place (`meta.place`, `data-mkp-place`), numbered as `places(source)` numbers them.

```js
import { outline } from './vendor/mkp/mkp-outline.js';
el.innerHTML = outline(source, sizes, { width: el.clientWidth, prose: (md) => myMarkdown(md) });
const { mount, mergeSizes } = await import('./vendor/mkp/mkp-dom.js');
mount(el, bundle, { places: true, onSizes: (s) => save(mergeSizes(sizes, s)) });
```

- **A pack's externs drawn by the host's own components.** An `extern` is drawn by the app's own code only, and there was no way to give `mount()` or React Native that code. Each renderer now takes `externs`, by id (`{ "myapp:accordion@1": … }`): React a component given `{ id, props, children, attrs, style, dispatch }` (MKP's own look kept, unlike `components`); `mount()` and `firstPaint()` a function `draw(box, { id, props, slot, dispatch })` that may return `{ update, destroy }`, so its own state is kept; React Native a component given `{ id, props, children, dispatch }`. `children` (or `slot`) is what the document put inside the extern, drawn by MKP. An extern with no component still shows a placeholder with its summary.

## Changed

- **`data-mkp-theme`.** MKP wrote `data-theme` on its root, so a host's own `[data-theme=light]` rules caught a light document inside a dark app. The root now says its theme with a name of its own; one paint holds both themes, so switching flips one attribute.

## Fixed

- **A pack's own type in a record field.** `type state = choice(none|done|todo)` with a field `state: state = todo` compiled with its fixtures, but a document that left the field out failed with `mkp.unknown-name: "todo"`: the default was read in the document's types, which can't see the pack's. Another pack's record lines failed the same way for given values. Both are now read in the types of the pack that declares the field.
- **An extern's outs.** `@toggled` written on an extern's use never ran: the runtime didn't wire an extern's handlers. A host reporting one with `dispatch` now runs them.

## Migration

From 0.2.6, `mkp migrate --write` changes only each file's stamp. A stored bundle gains its widgets' places (`meta.place`), so `mount(el, b, { places: true })` works with it too.
