# 0.2.4

Three hosts built on 0.2.3 and reported what got in their way. Most of this release is their reports: five fixes to `mkp migrate`, each from an exact repro, and the small things they asked for. Nothing written for 0.2.3 changes meaning; one drawing can change, the turns of routed arrows that share part of a gap (below).

## Breaking

- **Nothing for documents or packs, but arrows draw differently where they crossed or crowded.** The tracks in a gap are reordered where that crosses less, runs of different links closer than 8 px move apart, the crossings that remain get a hop, and turns that shared only part of a gap now turn apart. Graphs whose lines crossed nothing and crowded nothing draw as before. `arrow hop=none` keeps a line out of all of it. Code that builds arrow paths sees `ArrowPath.crowded`, hop arcs (`A`) in a path's `d`, and each arc on its own in `ArrowPath.hops`.

## New

- **Lines hop where they cross.** Where two links still cross, the flatter line lifts over the steeper one in a small arc (radius 5 px): a level run upwards, an upright one to the left; the other runs straight through. There is no hop where one line ends on another (a join), along a shared trunk, or within a hop of a corner, a head or a tail. Crossings closer than a hop make one wider hop. A dashed or dotted line keeps its dashes but draws the hop's arc as one unbroken stroke, so the hop always shows; links in front and `layer=behind` hop over each other the same way, and labels keep off a hop as off the rest of its line. Built once where the paths are made, so the web renderers and React Native draw the same. `arrow hop=none` (a sequence's lifelines, a rule) never hops, and nothing hops over it.

```mkp
crossing "Two links crossing at right angles, and a lifeline that never hops."
  column gap=l
    row gap=xl
      column pad=s
      column id=top pad=s stroke=ink radius=card
        text "top"
      column pad=s
      column id=life pad=s stroke=muted radius=card
        text "lifeline"
    row gap=xl
      column id=left pad=s stroke=ink radius=card
        text "left"
      column pad=l
      column pad=l
      column pad=l
      column id=right pad=s stroke=ink radius=card
        text "right"
    row gap=xl
      column pad=s
      column id=bottom pad=s stroke=ink radius=card
        text "bottom"
      column pad=s
      column id=end pad=s stroke=muted radius=card
        text "end"
    arrow from=left to=right
    arrow from=top to=bottom
    arrow from=life to=end line=dashed tone=line head=none hop=none
  project md = "left to right crosses top to bottom, and the lifeline"
```

```crossing
summary: Left to right hops over top to bottom; the dashed lifeline is crossed without a hop.
```

- **Icons `more` and `less`.** `prev` and `next` are chevrons, `up` and `down` arrows, so a disclosure that followed its state had to mix the two. `more` (∨) and `less` (∧) are the chevrons down and up: `icon name=(if(open, more, next))`. Both renderers draw them, and a host's own icons get the two names.

```mkp
disclosure "A section that opens, its chevron following it."
  var open bool = false
  column gap=s
    press kind=plain label="Details"
      row gap=s align=center
        icon name=(if(open, more, next)) size=small
        text "Details" weight=bold
      @click set open=(not open)
    text "What was hidden." if=open
  project md = "Details"
```

```disclosure
summary: A section whose chevron points down while it is open.
```

- **`arrow lanes=turn`.** A routed line through a via lane used to pass the lane at its middle, so a tall lane in a gap pulled the line up or down to it. With `lanes=turn`, a lane across the line's way says only where it turns, at the lane, keeping its ends' heights; one along its way is followed only as far as the line must. `full` stays the default.
- **One stylesheet for many documents.** Each document writes MKP's stylesheet (about 19 KB) and its tokens (about 2 KB). With `styles: 'external'` (`<MkpDocument styles="external">`, `mount(el, b, { styles: 'external' })`, `firstPaint(b, { styles: 'external' })`, `mkp build --target fragment --styles external`) it writes only its tokens, and the page loads the web zip's `mkp.css` once. `mkpCss()` is the same stylesheet, for a host's own. A first paint and the `mount()` that takes it over must agree.
- **`mkp-page.js` in the web zip:** `firstPaint()` for a build on Node, without the 8.8 MB CLI (React's server renderer inside).
- **The React Native renderer in the release:** `mkp-react-native-<version>.zip`, its source for Metro with a README on aliasing `@mkp/core` to the web zip's `mkp-runtime.js`, listed in `SHA256SUMS`.

## Changed

- **Fewer crossings.** Where several routed lines turn in one gap, their tracks are ordered so the fewest runs cross, counting the lines that pass straight through the gap; today's order is kept unless another crosses strictly less, so a graph that crossed nothing draws as it did.
- **No line hugs another.** Two runs of different links side by side closer than 8 px read as one, and a line that turned right beside another seemed to join it. The pass that makes the hops first moves such a run apart, trying the turn before the other line and past it (with room for a hop), and keeps whichever crosses least and moves least, only where its ends stay on their elements.
- **Turns in a shared gap keep apart.** Routed lines that turn in one gap get tracks at least 8 px apart where the gap has room: about 19 px for the runs before heads and after tails, then 8 px per line. Lines that share only part of a gap now each turn within their own. A gap too narrow for its turns marks those arrows `data-crowded` on the web: widen it.
- **YAML 1.1 words are quoted.** Printed YAML quotes `yes`, `no`, `on`, `off`, `y` and `n`, which a YAML 1.1 reader takes for booleans; MKP reads them the same either way.

## Fixed

- **A pack given to migrate and with `--pack`** reached the older release's core twice when it had no stamp (`mkp.pack-duplicate`). It is given once, and each pack is compiled with the run's other packs.
- **Documents waited for nothing.** When a pack in a run failed, its documents were still written, against the pack as it was. They are now left as they are, with an error naming the pack.
- **`mkp migrate --check` failed in silence** when a pack's other files lacked their stamp. Each such file now has a warning, `mkp.migrate-stamp`, and a run with nothing to change says `up to date (0.2.4)`.
- **A document migrated after its pack** failed with errors pointing at the pack. When a pack it is given is stamped newer, the first error says the order is the cause.
- **Defaults written into sources.** A record list printed as YAML wrote every field, defaults too (`note: ""`). Fields that only hold their default are left out, as record lines leave them out.
- **The migrate proof moved fixture cases meant to fail** (`expect.errors`) and required them to compile. It proves only valid cases.

## Migration

From 0.2.3, `mkp migrate --write` restamps each file and nothing else changes in a source. A stored bundle's list of icon names gains `more` and `less`. Migrate a pack and its documents in one run.
