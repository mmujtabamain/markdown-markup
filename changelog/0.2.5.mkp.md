# 0.2.5

One fix, from DevBench's report on 0.2.4: migrating a 0.2.3 pack rewrote about 400 lines of it into canonical form, though nothing in it changed. The 0.2.4 changelog had said only the stamp would change; that was wrong for 0.2.4, and is true from this release.

## Breaking

- **Nothing.** The only change to the API is `RELEASE`, the release's own number.

## Fixed

- **`mkp migrate` keeps a file's own text when the steps change nothing in it.** Every source goes through the IR and the printer, so until now each file came back in canonical form (`x=0..10` became `0..10`, parentheses dropped, prose rewrapped) even when no step touched it. Now each file is printed from its IR before and after the steps and a pack's moves; one that prints the same keeps its author's text, with only its stamp new, and the run says `nothing in it changes, restamped`. A file the steps do change is still written in canonical form. Documents, the `.mkp` file beside one, and packs alike.

```txt
$ mkp migrate lib/ notes/ --write
lib: 0.2.4 -> 0.2.5; nothing in it changes, restamped
notes/today.mkp.md: 0.2.4 -> 0.2.5; nothing in it changes, restamped
```

## API

### Changed

**JavaScript**

- const `RELEASE`: now `export declare const RELEASE = "0.2.5";` (was `export declare const RELEASE = "0.2.4";`)

## Migration

From 0.2.4, `mkp migrate --write` changes only each file's stamp, and keeps its text as you wrote it.
