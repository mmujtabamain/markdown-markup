# 0.2.0

MKP outside React: a renderer for any page or framework, and tested recipes for six stacks.

## Breaking

- **Fences go to Markdown first.** A fence labelled with a code language (`yaml`, `sh`, `ts`, any case), plain text (`text`, `txt`) or display maths (`math`, `latex`) is code or maths, even when its body looks like a widget's YAML. Only a label Markdown has no meaning for names a widget block. So a guide can show YAML or MKP in a fence without it being drawn, and the base widget `text` is no longer written as a fence: write it as a container, or as a widget of its own.

## New

- **`mkp-dom.js`: MKP without React.** `mount(el, bundle, { theme, onSignal })` draws a document into any element in MKP's own look, with its own React inside, so the page needs none. `update()` changes the theme or the signal handler and keeps the reader's place; `setBundle()` draws another document; `unmount()` removes it. It's in the web zip with its types, `mkp-dom.d.ts`.
- **Recipes for Vue, Svelte, Solid, Angular, Astro and plain JS.** Each is a small app in `recipes/` with a component to copy. Each is tested in a browser: it draws, the app hears the document's signals, a theme change keeps the reader's place, and it unmounts cleanly.
- **Docs and Examples on the website.** `/docs/` shows the repository's guides, compiled as MKP when the site is built, with a sidebar and an outline. The playground moved to `/examples/`, and old links open there.

## Changed

- **HTML comments in a document draw nothing**, and `$` inside code is no longer read as maths: a shell variable in a code block stays a shell variable.

## API

**IR and files**

- `mkp-dom.d.ts` in the web zip
- `mkp-dom.js` in the web zip

## Migration

A document that wrote a widget block under a fence label Markdown knows (`text`, a language name) is now a code block. Rename the block's label to the widget's name, or write it as a container.
