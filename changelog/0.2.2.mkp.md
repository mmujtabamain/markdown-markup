# 0.2.2

A large release, from building two hosts' libraries on MKP: one drew its release notes with MKP widgets that replicate its own components, the other a study app's plots, graphs and walks. Every claim on their lists was checked against the source before anything changed; what didn't hold is said below. It also brings migrations: from now on every file says which release wrote it, and `mkp migrate` brings anything older up to date.

## Breaking

- **`theme` is a name every definition reads.** Like `width`, `theme` is now `light` or `dark`, the reader's theme. A definition that declares its own `theme` (an input, a var, a value, a fn, a control or an `each` variable) is refused with `mkp.shadow`. `mkp migrate` renames yours (to `look`, or `look2` if that is taken) in the definition, every use of it, documents' YAML and the pack's fixtures. An app that sets that input by name has to follow by hand.
- **Arrows touch what they join.** The 3 px gap at each end is gone, and a routed line keeps a straight run before its head (the head and 6 px) and after its tail, moving its turn off the middle of a narrow gap if it has to. The old look can't be kept; `mkp migrate` names each arrow that changes (`arrow-ends`).
- **`self=` places a child on both axes in a grid or a stack.** `self=start` is now the top-left corner of the cell, where it used to stretch across. In rows and columns nothing changed. One-axis placement can't be written; set the container's `align=` instead (`self-both-axes`).
- **A zoom shrinks a wide drawing no smaller than 0.6.** Past that it shows the middle, clipped, and the reader pans once unlocked. `zoom minscale=0` keeps the old fit; `mkp migrate --keep zoom-minscale` writes it for you.
- **The renderers need `mkp-runtime.js` beside them.** `mkp-react.js` and `mkp-dom.js` now import the core's runtime half, `mkp-runtime.js`, which imports `mkp-shared.js`. All three are in the web zip; keep the zip's files together, as before.

## New

- **Shapes inside a widget can be pointed at and pressed.** A canvas `circle` or `path` takes `@enter`, `@leave` and `@click`, so a chart's slices can light up and be pressed, and containers take `@enter` and `@leave`. Nothing of the pointer reaches the document (no position, no buttons). A shape that takes `@click` needs a `label=` and becomes a focusable button, pressed with Enter or Space; its canvas becomes a group of controls. A clicked shape no longer gets a box drawn round it: keyboard focus traces its own edge.

```mkp
spend "A pie whose slices light up under the pointer and can be pressed."
  in items list(record slice {label: text, value: num})
  var on int = -1
  var picked int = -1
  total = sum(map(items, s => s.value))
  now = if(on >= 0, items[on].label, "nothing")
  chosen = if(picked >= 0, items[picked].label, "none yet")
  fn before(k: int): num = sum(map(filter(range(0, len(items) - 1), i => i < k), i => items[i].value))
  fn ang(t: num): num = pi / 2 - 2 pi t
  fn wedge(k: int): list(point) = [(0, 0)] + map(range(0, 30), j => (cos(ang((before(k) + items[k].value * j / 30) / total)), sin(ang((before(k) + items[k].value * j / 30) / total))))
  fn hue(k: int): color = if(k == 0, c1, if(k == 1, c2, c3))
  row gap=l align=center
    canvas -1.05..1.05 -1.05..1.05 size=s label="spending"
      layer
        each k in 0..(len(items) - 1) key=k
          path wedge(k) closed=true fill=(if(on == k, ink, hue(k))) stroke=surface width=2 label=items[k].label
            @enter set on=k
            @leave set on=-1
            @click set picked=k
    column gap=s
      text "Pointing at **\val{now}**"
      text "Pressed **\val{chosen}**"
      text "A pressed slice is a button too: Tab to it, then Enter." size=small tone=muted
  project md = join(map(items, s => "- " + s.label + ": " + format(s.value, 0)), "\n")
```

```spend
items: [{label: Rent, value: 900}, {label: Food, value: 300}, {label: Travel, value: 150}]
summary: Spending as a pie you can point at.
```

- **Arrows meet what they join, with a straight run before every head.** `arrow corner=m|s|none` sets how round a routed line's turns are (12 px, 6 px, square).

```mkp
tree "A parent over three children, eight pixels apart; the right-hand line has corner=none."
  column
    grid cols=[1fr, 1fr, 1fr] gap=m
      column pad=s stroke=line radius=card id=p span=3 self=center
        text "parent"
      column pad=s stroke=line radius=card id=a
        text "left"
      column pad=s stroke=line radius=card id=b
        text "middle"
      column pad=s stroke=line radius=card id=c
        text "right, square turns"
    arrow from=p to=a route=down
    arrow from=p to=b route=down
    arrow from=p to=c route=down corner=none
  project md = "A parent over three children."
```

- **Lines drawn behind show inside a frame.** A frame's stage is now a layer for the arrows between what it holds, so a line `layer=behind` sits over the frame's surface and under its content, instead of vanishing under the surface.

```mkp
calls "Two parties in a frame, the call between them drawn behind."
  frame kind="Sequence" title="A request"
    row gap=xl pad=m justify=between
      column pad=s stroke=line radius=card fill=surface id=client
        text "client"
      column pad=s stroke=line radius=card fill=surface id=server
        text "server"
  arrow from=client to=server layer=behind tone=accent "GET /notes"
  project md = "The client asks the server for its notes."
```

- **`padx=` and `pady=` on the four containers.** They take a space token each and pad the sides, or the top and bottom, in `pad`'s place there: `row padx=l pady=xs` for a list row.

```mkp
rows "Rows padded more at the sides than above and below."
  in items list(text)
  column stroke=line radius=card width=fit
    each k in 0..(len(items) - 1) key=k
      row padx=l pady=xs edge=bottom stroke=(if(k < len(items) - 1, line, none))
        text (items[k])
  project md = join(map(items, s => "- " + s), "\n")
```

- **A canvas layer can be clipped.** `layer clip=[(x0, y0), (x1, y1)]` cuts the layer's shapes off outside that rectangle, in data units, so a plot's curves stop at its axes' margin. It works on the web, in React Native and in the Markdown picture.

```mkp
wave "A curve that stops at the plot's edge, inside the axes' margin."
  var k num = 3
  canvas -0.2..6.6 -1.4..1.4 size=m label="a sine wave, clipped"
    layer
      path [(0, -1.2), (0, 1.2)] stroke=line
      path [(0, 0), (6.3, 0)] stroke=line
      label (-0.1, 1) "1" anchor=e size=small tone=muted
      label (-0.1, -1) "−1" anchor=e size=small tone=muted
    layer clip=[(0, -1.2), (6.3, 1.2)]
      path (map(range(0, 120), i => (i / 15 - 0.5, 1.3 sin(k i / 15)))) stroke=accent width=2
  project md = "A sine wave, clipped to its plot."
```

- **A widget can read the theme.** `theme` is `light` or `dark` as the reader sees the page. Colour tokens follow the theme on their own; read `theme` for what can't use them, such as a `pixels` ramp. Markdown is drawn `light`. The renderers set it (`auto` follows the system); a host with its own roots calls `useMkpTheme(theme)` or `rt.setTheme()`.

```mkp
look "What the reader's theme is, for drawings that can't use the colour tokens."
  row gap=s align=center padx=m pady=s tint=(if(theme == dark, info, warn)) radius=card width=fit
    icon name=(if(theme == dark, eye, lightbulb))
    text "This page is **\val{theme}**: switch the site's theme to see it change."
  project md = "The reader's theme."
```

```look
summary: The theme.
```

- **`slot body if=(…)`.** A slot is placed only while its condition holds, without a wrapping container.

```mkp
part fold "A heading that opens to show what it holds."
  fields title
  in title text
  in body slot
  var open bool = false
  mark = if(open, "▾", "▸")
  column gap=s
    press kind=plain label=(title)
      text "\val{mark} \val{title}" weight=bold
      @click set open=(not open)
    slot body if=(open)

more "A folded section."
  fold "More detail"
    text "Shown by slot body if=(open)."
  project md = "More detail, folded."
```

- **Pages drawing documents built ahead of time load no compiler.** The release has `mkp-runtime.js`, the core's runtime half alone. The renderers import it, so a page that draws prebuilt bundles loads about 550 KB instead of 1 MB. `mkp.js` and `mkp-runtime.js` share `mkp-shared.js`, so a page that compiles too loads each part once.

```js
import { mount } from './vendor/mkp/mkp-dom.js';   // with mkp-runtime.js: about 550 KB, not 1 MB
mount(el, bundle);                                 // the maths engine only if the document needs it
```

- **A first paint that `mount()` takes over in place.** `mkp build --target fragment` (or `firstPaint()` in `@mkp/page`) writes the document as `mount()` first draws it. Put it in the page on the server, then `mount(el, bundle, { hydrate: true })`: the same elements become live, so nothing is swapped and nothing moves. A first paint that isn't this bundle's is drawn again, with a warning.

```sh
mkp build note.mkp.md --target ir,fragment --out out   # note.fragment.html: the page's first paint
```

```js
mount(el, bundle, { hydrate: true });   // the same elements, now live: nothing is swapped or moves
```

- **The maths engine loads only when it's needed.** `needsMaths(bundle)` says whether drawing needs the engine: maths the build hasn't typeset, maths with live values, or text that may become maths as it runs (`"$" + name + "$"`). `mount()` and `--target html` pages ask it, so a document with no maths never fetches the 2.7 MB engine.
- **`tokens` on `mount()`**, as `<MkpDocument>` has, and a class per press kind: every press has `mkp-press-<kind>` as well as `mkp-press`, so a host's stylesheet can style buttons without catching switches, checks or cards.
- **Migrations between releases.** Every bundle, lock and source now says which release wrote it (`"mkp": "0.2.2"` in a bundle, `mkp: 0.2.2` in a document's front matter, `# mkp 0.2.2 ir 1` as a `.mkp` file's first line). `mkp migrate` compiles a file with the release it was written for, runs every release's step up to this one, writes it back in canonical form and checks it before writing. Each change is a warning at its line, and where an old look can be kept, you choose. `mount()` upgrades an older stored bundle as it loads. The website's Migrations tab shows each release's step.

```sh
mkp migrate lib/ notes/ --write          # each file compiled by its own release, updated, checked, stamped
mkp migrate notes/ --pack lib --check    # in CI: fails while anything is written for an older release
```

- **A pack's own versions.** Mark an old version `deprecated "use walk@2: …"` (every use is warned), and say how a use moves with `migrate walk@1 -> walk@2` (`rename`, `drop … "why"`, `keep … = value "why"`). `mkp check` proves it on the old version's fixtures and `mkp migrate` moves the uses.

```txt
walk@1 "A walk."
  deprecated "use walk@2: from is now start"
  …

migrate walk@1 -> walk@2
  rename from -> start
  keep look = classic "walk@1's look"
```

## Changed

- **A switch's track and thumb are elements**, `.mkp-switch > .mkp-switch-thumb`, no longer a `::before` gradient, so a host can trace or animate the thumb. MKP still animates nothing; give the thumb a `transition` to make it slide.
- **`help` is drawn in a ring** in MKP's own look, as `info` is, and every icon carries `data-name`, so a host can swap in its own symbol.
- **`each`, `switch` and `case` don't count toward the 12 levels of nesting.** Only containers do.
- **A steps bar's track gives way first** on a narrow screen, so the buttons and count keep one line.
- **The guides** now say the order actions run in on one line (left to right, each seeing the one before), show a text field per step, and list what the page's elements promise to a host (`data-mkp-id`, `data-mkp-def`, the press classes) and what they don't.

## Fixed

- **A dimmed or blurred layer of a stack painted over the layers after it**, so a button over a faded picture couldn't be seen or pressed. Every layer is now positioned, so they paint in the order written.
- **A tail shared by several lines was drawn once per line** on a combined trunk; each mark is now drawn once.
- **The base set's own corner badge stretched across its picture** (`self=start` in a stack), fixed with `self=` placing both ways.

## Migration

From 0.2.1, `mkp migrate lib/ notes/ --write` brings packs and documents up to date. By itself it renames a `theme` you declared, adds the canvas records' new fields, and stamps every file. It asks about one look you can keep, the zoom's old fit (`--keep zoom-minscale`). Check by hand: an app that set an input called `theme` by name, and drawings where arrows, `self=` in a grid or stack, or a dimmed stack layer now look different. Stored bundles migrate on load in `mount()`, or with `migrateBundle()`. The Migrations tab has the before and after.
