# 0.2.3

A small release that finishes two things 0.2.2 started. A pack's `migrate` block could only move a widget's uses to its own next version, input by input; now it can move them to another widget, reach into the items of a record list, and change a choice's values. And a host could only restyle MKP's icons with CSS; now every renderer draws the host's own. Nothing that was written for 0.2.2 changes meaning or look.

## Breaking

- **For code that calls the pack-move functions only.** `moveProps()` (in `mkp.js`) takes a `ValueForm`, which says how values are held (IR values, or a fixture's JSON), where it took a function for kept values. `PackMove` gained `fields`, `map` and `records`. Documents, packs and bundles are not affected, and neither is `mkp migrate`.

## New

- **A pack's uses can move to another widget.** `migrate statuslist@1 -> rows@1` moves every use of `statuslist@1` to `rows@1`, in the same pack, or `ui:rows@1` in a pack this one depends on. The block lives in the pack of the old widget, and `mkp migrate` moves documents, the pack's own definitions and stored bundles alike.

  ```txt
  migrate statuslist@1 -> rows@1
    rename items -> rows
    rename items.name -> rows.title
    rename items.state -> rows.tone
    drop items.icon "rows show no icon"
    map items.state: done -> ok, todo -> muted, late -> bad
  ```

- **A dotted name reaches a field of each item of a record list.** `rename items.name -> rows.title` and `drop items.icon "why"` work on items written as YAML lists and as record lines (`item "Tea" done`). The new side names the list the old one became.
- **`map` changes a choice's or a text's values, one for one.** `map items.state: done -> ok, late -> bad`, or `map tone: good -> ok` for an input. A value that is an expression is left as it is, and the recompile after migrating says if it no longer fits.
- **The check covers fields and values as it covers inputs.** Every field of the old items goes somewhere, every field the new items need is given or has a default (filled in for stored bundles), and every value of an old choice is one the new choice takes, as it is or mapped. `mkp check` then proves the block on the old widget's fixtures, against the new widget's pack. `mkp migrate`'s warning at each use lists every rename, drop and map.
- **Your icons, in every renderer.** MKP still draws its icons as text symbols, and documents still only name icons from the fixed set; what draws them can now be yours.
  - `@mkp/react`: `<MkpDocument icons={HelpIcon} />` for every name, or `icons={{ help: HelpIcon }}` for some. Any component, given `{ name, size, tone, color, label, className }`.
  - `@mkp/react-native`: the same, given `{ name, size, tone, color, px, label }`.
  - `mount()` and `firstPaint()`: an SVG string, put in the box as given (so a first paint and `mount()` agree, and hydration keeps it), or `(box, props) => cleanup` for icons from another framework.

  ```ts
  mount(el, bundle, { icons: { help: helpSvg, info: (box, { color }) => drawInfo(box, color) } });
  ```

  The box stays MKP's: `.mkp-icon` with `data-name`, `data-size`, its colour and its label, now with `data-tone` and `data-host`. MKP's symbol is left out of it. The markup is the host's own, so MKP puts it in as given.

## Changed

- **A breaking change to a pack's widget is a new version beside the old one** (`callout@2` next to `callout@1`), never an edit of the old one, and it comes with a `migrate` block. The authoring and integration guides say so, and the Migrations tab shows both kinds of block.
- **What's new reads each release's changelog.** Every release from 0.1.0 has a full changelog (`changelog/<version>.mkp.md`), with its API section made from the releases themselves. The tab has kind filters, a word search with marks, folding, a Versions index, anchors with a copy link, live demos, a feed and a page that reads without scripts. GitHub's release notes stay short and link to it.
- **`pnpm api:diff` and `pnpm check:api`.** The first prints a release's API section from the two releases' files (JavaScript types, the language, the CLI, the IR and the web zip); the second warns in CI about a change the changelog doesn't name.

### Added

**JavaScript**

- interface `HostIconProps` in `mkp-dom.js`
- type `DomIcon` in `mkp-dom.js`
- type `DomIcons` in `mkp-dom.js`
- `MountOptions.icons`: `icons?: DomIcons;`
- function `hostIcon` in `mkp-react.js`
- function `domIcons` in `mkp-react.js`
- interface `HostIconProps` in `mkp-react.js`
- type `IconComponent` in `mkp-react.js`
- type `MkpIcons` in `mkp-react.js`
- type `DomIcon` in `mkp-react.js`
- type `DomIcons` in `mkp-react.js`
- `Ctx.icons`: `icons?: MkpIcons;`
- `MkpProviderProps.icons`: `icons?: MkpIcons;`
- `MkpDocumentProps.icons` in `@mkp/react-native` (used from source): `icons?: MkpIcons;`, with its own `HostIconProps` (`px` in place of `className`) and `hostIcon`
- function `moveSummary` in `mkp.js`
- function `moveItem` in `mkp.js`
- const `moveNames` in `mkp.js`
- interface `ValueForm` in `mkp.js`
- `PackMove.fields`: `fields: Record<string, { rename: Record<string, string>; drop: { name: string; why: string; }[]; }>;`
- `PackMove.map`: `map: Record<string, Record<string, string>>;`
- `PackMove.records`: `records: Record<string, { kind: string; fill: Record<string, IRVal>; }>;`

### Changed

**JavaScript**

- function `Icon`: now `export declare function Icon({ n, attrs, style, icons }: { n: VNode; attrs?: Record<string, unknown>; style?: CSSProperties; icons?: MkpIcons; }): ReactNode;` (was `export declare function Icon({ n, attrs, style }: { n: VNode; attrs?: Record<string, unknown>; style?: CSSProperties; }): ReactNode;`)
- function `moveProps`: now `export declare function moveProps<T>(props: Record<string, T>, move: PackMove, keep: boolean, form: ValueForm<T>): Record<string, T>;` (was `export declare function moveProps<T>(props: Record<string, T>, move: PackMove, keep: boolean, val: (v: IRVal) => T): Record<string, T>;`)
- type `MoveLine`: gains `{ k: "map"; name: string; values: [string, string][]; p: Pos }`, a `map` line
- const `RELEASE`: now `export declare const RELEASE = "0.2.3";` (was `export declare const RELEASE = "0.2.2";`)
- type `FileItem`: a `migrate` item's lines can be `{ k: "map"; name: string; values: [string, string][] }`

## Migration

From 0.2.2 there is nothing to change: `mkp migrate --write` only restamps each file (`mkp: 0.2.3`, `# mkp 0.2.3 ir 1`). Files written for 0.2.2 keep working as they are. Code that calls `moveProps()` passes a `ValueForm` in place of its value function (see Breaking).
