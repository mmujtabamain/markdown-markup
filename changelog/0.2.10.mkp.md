# 0.2.10

From two hosts' reports on 0.2.9: a widget given both `minheight` and `aspect` overflowed a phone's column, and a host that bakes each widget's first paint at build time asked for MKP's own way to split a document. Nothing written for 0.2.9 changes meaning.

## Breaking

- **A state block has a place.** `meta.place` (and `data-mkp-place`) now counts a document's `state` blocks as well as its widgets, so a widget after one is numbered one higher; a bundle built before is numbered again when it is migrated. `outline()`, `places()` and `segments()` count them the same way.
- **Nothing for documents or packs.** `sizeStyle()` now also returns `maxWidth: '100%'`, and a sized widget's minheight and aspect are custom properties (`--mkp-minheight`, `--mkp-aspect`) on an element marked `data-mkp-sized`, read by MKP's stylesheet, rather than `min-height` and `aspect-ratio` on it. A host extern given a size is drawn inside a box of MKP's own, which carries its `data-mkp-*` attributes.

## New

- **`segments(source)`.** A document's pieces in order, each its source lines as written (so they put back together give the document): prose, each top-level widget with its place (as `meta.place` and `data-mkp-place` number it) and name, and the front matter, `mkp` definitions and `state` blocks around them. A widget that uses the document's own widgets or shared state doesn't compile from its own text alone: those pieces are what it needs, and what a cache of its first paint should be keyed on too. In `mkp.js`, `mkp-outline.js` and `mkp-dom.js`.
- **`\val{}` in prose is warned of.** `\val{n}` shows a live value in a widget's text (`text "\val{n}"`); written in a document's prose it was shown as the characters `\val{n}`, with no word from the compiler. It is now warned of where it is written (`mkp.val-in-prose`); code, inline or fenced, is left alone.

- **A bundle carries its images, so its design is frozen with it.** A pack's images that its widgets or the document name in a string (`image "frames/open.svg"`, or `if(open, "frames/open.svg", "frames/closed.svg")`) are copied into the bundle (`assets`, by `pack/path`: an SVG as the pack cleaned it, a picture as base64), each digest in the bundle's lock. Until now a pack's images were checked and then dropped, and an image was only ever its URL. Renderers draw a carried image from the bundle as a data URI, never fetched, so a bundle looks the same however its pack, or the app it came from, changes later: what a release note needs to show a frozen picture of an app's screen, with MKP's presses, hover and state over it (swapping frames). On React Native a carried SVG is drawn with react-native-svg (`SvgXml`); before, an SVG image showed nothing there. The Markdown target writes a carried SVG beside the Markdown, named as in its pack. An image the bundle doesn't carry keeps its `src` as written.

## Fixed

- **`minheight` with `aspect`.** 0.2.9 wrote `min-height` and `aspect-ratio` on the widget's own box. Together they set a least width as well, so `minheight: 240` with `aspect: 3` made a 720 × 240 box in a 372 px column, and a set `min-height` stops an aspect box from growing for its content, so a graph laid out tall on a phone (570 px) painted over the next block. The widget now holds a spacer that only reserves room (`aspect` and `minheight`, never wider than the column), and its content beside it: the box is the larger of the two. Measured in Chromium for each pair, at 372 and 1000 px, with short and tall content: the placeholder and the drawn widget are the same size when the content fits, and the box grows when it doesn't. The placeholder is never wider than its column.

- **A widget's own lone size warned on every use.** A widget that gives itself only `minheight` (its height follows its data) made every document that used it say `mkp.size`, though the document's author wrote no size, while its pack checked clean. The warning is now said once, at the widget's `in minheight` line, when its pack (or the document's own definitions) is checked; a use is warned only of a lone size it writes itself.
- **A host's extern wasn't spaced like a widget.** In a document an extern's box had no gap above it and the paragraph after it 8 px, where a widget has 16 px each side. An extern's element now carries `data-mkp-ext` (its id), and MKP's stylesheet spaces it as it spaces a widget, its placeholder too.
- **With `places: true`, a document's `state` controls and its footnotes were drawn nowhere, silently.** A `state` block now has a place: `outline()` gives it a box as tall as its controls are drawn (measured in Chromium: 21 px a row, 11 px between), and `mount()` draws them there. Footnotes are prose, so the page's renderer draws them, as it draws the rest; the integration guide now says so. Anything MKP draws that has no box is said of once on the console.
- **CI no longer fails when GitHub's release downloads do.** The published releases the tests and the API check compare with, and the Hermes CLI, are kept between runs (`actions/cache`); they never change.

## API

### Added

**JavaScript**

- function `segments` in `mkp.js`, `mkp-outline.js` and `mkp-dom.js`
- type `Segment` (the same)
- function `sizeVars` in `mkp.js`
- interface `IRAsset` in `mkp.js`
- `IRBundle.assets`: `assets?: Record<string, IRAsset>;`
- `IRLock.assets`: `assets?: Record<string, string>;`

**IR and files**

- `bundle.assets` (optional)
- `bundle.lock.assets` (optional)

### Changed

**JavaScript**

- function `sizeStyle`: now `export declare function sizeStyle(s: WidgetSize): { minWidth?: string; minHeight?: string; aspectRatio?: string; maxWidth?: string; };` (was `export declare function sizeStyle(s: WidgetSize): { minWidth?: string; minHeight?: string; aspectRatio?: string; };`)
- type `VShape`: an image gains `asset?: string`, the bundle's image it is drawn from
- const `RELEASE`: now `export declare const RELEASE = "0.2.10";` (was `export declare const RELEASE = "0.2.9";`)
