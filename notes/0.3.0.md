## New
- **`mkp-runtime.js`: draw without the compiler.** The core's runtime half, on its own. `mkp-react.js` and `mkp-dom.js` now import it, so a page that draws documents compiled ahead of time loads about 550 KB instead of 1 MB. `mkp.js` and it share `mkp-shared.js`, so a page that loads both loads each part once.
- **A first paint `mount()` takes over.** `mkp build --target ir,fragment` writes `name.fragment.html`, the document as `mount()` first draws it. Put it in the page on the server and call `mount(el, bundle, { hydrate: true })`: the text and widgets show at once, and nothing is swapped or moves. `firstPaint()` in `@mkp/page` does the same from code.
- **Hover and press inside a widget.** A canvas `circle` or `path` takes `@enter`, `@leave` and `@click`, so a chart's slices can light up and be pressed. A pressed shape needs a `label=` and becomes a focusable control. Containers take `@enter` and `@leave` (pointer only). The events carry no position or other pointer data.
- **`tokens` on `mount()`**, as `<MkpDocument>` has.
- **A class per press kind.** Every press has `mkp-press-<kind>` as well as `mkp-press`, so your stylesheet can style buttons without catching switches, checks or cards.
- **`needsMaths(bundle)`** says whether a document needs the maths engine to draw, including maths joined from text as it runs (`"$" + name + "$"`).
- **`theme`**, `light` or `dark`, read like `width`: a drawing that can't use colour tokens (a pixels ramp) can follow the reader's theme. The renderers set it; with your own roots, call `useMkpTheme(theme)`.
- **`padx=` and `pady=`** on containers, **`layer clip=[(x0, y0), (x1, y1)]`** on a canvas, **`zoom minscale=`**, **`arrow corner=m|s|none`**, and **`slot body if=(…)`**.
- **What's new on the website.** A new tab lists each release's changes, one line each, with the change working live under it.
## Changed
- **Breaking: `theme` is a reserved name**, like `width`. Rename an input, var or value called `theme`.
- **Arrows touch what they join.** No more 3 px gap at either end. A routed line keeps a straight run before its head and after its tail, moving its turn off the middle of a narrow gap if it must.
- **`self=` places a child on both axes in a grid or a stack**, so a badge sits in its corner instead of stretching across. In rows and columns it is unchanged.
- **A zoom shrinks a wide drawing no smaller than 0.6** by default. Past that, the middle shows and the reader pans. `minscale=0` restores the old fit.
- `each`, `switch` and `case` no longer count toward the 12 levels of nesting.
- A frame's stage draws the arrows between what it holds, so lines `layer=behind` show over its surface.
- **The maths engine loads only when it's needed.** `mount()` (with the default `maths: 'auto'`) and `--target html` pages no longer fetch it for a document with no maths, or whose maths the build already typeset.
- **A switch's track and thumb are elements** (`.mkp-switch > .mkp-switch-thumb`), no longer a `::before` gradient. MKP still animates nothing: give the thumb a `transition` to make it slide.
- **`help` is drawn in a ring** in MKP's own look, as `info` is, and every icon carries `data-name`.
- A dimmed or blurred layer of a stack no longer paints over the layers after it, and a tail shared by several lines is drawn once.
- A canvas shape that can be pressed no longer gets a box drawn round it when it is clicked: keyboard focus traces the shape's own edge instead.
- The integration guide lists what the page's elements promise (`data-mkp-id`, `data-mkp-def`, the press classes and more), and the authoring guide says the order actions run in and shows a text field per step.
