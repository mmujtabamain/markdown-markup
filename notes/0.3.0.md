## Changed
- **Breaking: MKP is now Extended Mark.** Documents are `name.xt.md` (were `name.mkp.md`), definitions files `name.xtpack` (were `name.mkp`), the project file `xtmd.toml` (was `mkp.toml`), the command `xtmd` (was `mkp`), the npm packages `xtmd` and `@extended-mark/*` (were `@mkp/cli` and `@mkp/*`), and the crates `xtmd-*` (were `mkp-*`). `xtmd migrate` renames a 0.2 document as it moves it.
- **Breaking: Extended Mark 0.3 is a new version of the language.** A document written for 0.2 is moved to it by `xtmd migrate`, which runs 0.2.10's own compiler and the migrator first; an `xtmd.toml` beside the tree then says which version it is written for.
- **One compiler.** `xtmd` (the command, and the `xtmd` npm package for build tools) is the only thing that turns Extended Mark into the IR every target runs; a page's IR holds only what it uses.
## New
- **A checked language.** Types, contracts and the proofs they need, what a fn may change, and every rule of the spec, each held to a conformance case.
- **Two kinds of target.** A run-time target draws an IR built ahead and carries no compiler; a real-time target compiles the text where it runs (`@extended-mark/wasm` in a browser), for an editor or a live preview.
- **Targets for the web, React, Vue, Svelte, Solid and Angular, egui and Android's Compose**, each in both kinds, each passing the same conformance cases.
- **Packs with versions and migrations**, and `xtmd migrate` to move documents and packs between them.
- **Editors: `xtmd lsp`, a language server** (ide/lsp): errors as you type, hover, go to definition, references, the outline, completion and formatting, for any editor with a language client.
- **Extended Mark for VS Code** (ide/vscode, `xtmd-0.3.0.vsix` with the release): the language server built in, so nothing to install and vscode.dev works too, and a live preview drawn by VS Code's own components, the `vscode` target. Show as Markdown, Check a Folder and Migrate run in the extension itself, from xtmd.wasm: Migrate shows every change before it writes them, as one edit that Undo takes back.
- **Blocks in prose may be indented.** A block's lines are read with their common indent taken off, as a `markdown` block's are, so an `@if` inside an `@for` reads as nested code does, and `xtmd fmt` indents each block four spaces past its opening line. A flat page reads the same as before.
- **Did you mean…?** A name that names nothing is answered with the one it most likely meant, when one is a slip away: an unknown widget, input, slot, name, field, case, type or fn. With `--format json` the fix comes as edits (`"edits": [{ line, column, end, text }]`), and an editor applies it in a click.
- **For tools:** `xtmd fmt --stdin` formats a text that isn't saved, `xtmd build --rir --core` puts core's declarations in the resolved IR, and `@extended-mark/wasm` gives the resolved IR, formatting and the language server from text.
- **`xtmd` for Linux, macOS and Windows**, installed with `npm i -g xtmd` (or `npm i -g extended-mark`, the same by the language's name); where no binary fits, `build` and `check` run the compiler as WebAssembly.
